## Gitee Go 流水线配置全程（pipeline-linux-x86_64 / linux-x86_64.yml）

- **背景**：Gitee Go 流水线执行的是**编辑界面缓存配置**，不是代码库 yml；代码库 yml 与编辑界面**不会自动同步**（双源割裂）。改代码库文件不影响已保存的流水线运行配置。
- **版本号需求**：产物名 `tds-v{提交总数}-linux-x86_64-{yyMMdd}.tar.gz`。
  - Gitee API 取提交总数：`GET /api/v5/repos/liangtuSoft/tds/commits?per_page=100` 的**响应头**有 `commit_count`/`total_count`（实测 2640），公开仓库免 token，匿名限流 60 次/时。
  - build 步骤取数：`COMMIT_COUNT=$(curl -s -D - -o /dev/null "https://gitee.com/api/v5/repos/liangtuSoft/tds/commits?per_page=1" | tr -d "\r" | awk -F": " "/^[Cc]ommit_count/{print \$2}")`，再 `export TDS_VERSION_OVERRIDE="tds-v${COMMIT_COUNT:-unknown}-linux-x86_64-$(date +%y%m%d)"`。package.sh 里 TDS_VERSION_OVERRIDE 整体替换 VER。
- **release@gitee 插件关键事实**（官方文档）：
  - `assertFiles` 是**唯一**的附件挂载通道（"附加到 Release 的文件路径"，基于流水线执行时工作目录）；`upstreamArtifact` 只是把 build 产物目录带给插件引用，**不会自动上传**。不填 assertFiles 时 release 只显示 Gitee 自动打的源码 zip/tar.gz。
  - `releaseName`/`tagName`/`assertFiles` 是**保存时静态字段**，只能引用系统参数（GITEE_PIPELINE_BUILD_NUMBER、GITEE_COMMIT_SHORT 等），拼不出运行时算出的"提交次数+日期"。故 releaseName/tagName 用 `tds-${GITEE_COMMIT_SHORT}-linux-x86_64`。
  - 之前的错误做法：误删 assertFiles 导致 release 只挂源码。已修正：assertFiles 填 `./out/dist/*.tar.gz` + 固定名兜底 `./out/dist/tds-linux-x86_64.tar.gz`（build 步骤加 `cp out/dist/tds-v*-linux-x86_64-*.tar.gz out/dist/tds-linux-x86_64.tar.gz` + `ls -la out/dist/`）。
